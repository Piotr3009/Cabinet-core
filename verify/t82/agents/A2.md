## THE ONE FUNCTION (the contract A3, A4, A5, E3 read; never re-derive)

```js
import { hawaPocketFigures, pocketCoverOf, hawaPocketWidth } from '../engine/hawaPocket.js';

// THE STORE (A3) hands the engine, for a HAWA_POCKET:
//   params.pocket       { doors: 1 | 2, hand: 'L' | 'R' | null, push, cls: 25 | 35 | null, covers: [ids] }
//   params.pocket_cover = pocketCoverOf(pocketUnit, coveredUnitsInOrder, profile, { beyond: { L, R } })
//     coveredUnitsInOrder: an array nearest first (one door: the hand's side;
//       two doors: each unit's side read from where it stands) or { L: [...], R: [...] }
//     beyond: what stands past the last covered unit's far edge, a frontClearance kind
//       ('front' | 'endPanel' | 'infill' | 'appliance' | 'wall' | 'none'; absent 'none');
//       a covered unit's own end panel on its far side is 'endPanel'
//     -> { doors: [{ side, units, unitNums, spanMm, KT1, far, freeEndClearanceMm, drawerFronts }] } | null
//   and, to each COVERED unit, params.pocket_covered = { pocketId, unitNum } (drops its own doors)
// and keeps params.width = figures.widthMm, params.depth = figures.KT, and the pocket's back
// stood off by figures.frontAlignMm so its front plane is the covered cabinet's.

hawaPocketFigures(params, profile) -> {
  count, hand, push, clsAsked, covers, frontT, S,
  panel: { t, swapped }, clearMm, widthMm, H, EH, TH, KT, KT1, frontAlignMm,
  connectorName,                     // 'Hawa Connector 55' | 'Hawa Connector 110'
  zones: { top: 63, bottom: 50, hardware: 17 },
  parts: [{ part, id, kind: 'A' | 'B' | 'top' | 'bottom' | 'door', side, w, h, t, box, holes, grooves? }],
  doors: [{
    id ('POCKET-DOOR' | 'POCKET-DOOR-L' | 'POCKET-DOOR-R'), side, covers, unitNums,
    hawaHand: 'left' | 'right', setName ('Hawa Concepta III 25 Push, left' | null when refused), push,
    spanMm, far, freeEndClearanceMm,
    TB, TH, S, cls (25 | 35 | null = refused), clsAsked, clsAuto, hinges (3 | 4 | null),
    TA, Zhinge, Z1, Z2, proud,
    T1, M, E1, KT1, trackMm (T1 - 7), steelMm (TB - M + 3 for III/35, else null),
    weightKg, maxKg, hingeEdge ('L' | 'R', seen from the room), cupY (from the door's bottom),
    holes, grooves (the LISP's (layer u v d depth) and (u0 v0 u1 v1) in the door's face frame),
    closed: { x, y, z, w, h, d }, open: { x, y, z, w, h, d },   // the unit's box frame
  }],
  refusals: [{ n: 37 | 38, code, side, unit?, message }],   // the LISP's sentences verbatim
  notes: [{ n: 47, code, message }],
  ok,
}
computeCabinet(params, profile).hawa  // deep-equal to it: read unitResult(id).hawa
hawaPocketWidth({ doors, frontT }, profile)  // the width at birth, before any cover
```

Every pocket panel carries `meta.pocket.kind` ('A' | 'B' | 'top' | 'bottom' |
'door'), `side`, `holes` (the LISP's rows in its face frame: u from the panel's
front edge, v from its bottom, on its pocket face; the door's u from its hinge
edge on its back face) and the door `grooves`. A4's CNC turns those into drill
records and pockets; nothing in the cut drills them yet (`cnc` is the

## DECISIONS TAKEN

1. TB is the LISP's (D6): one door TB = span + B + (55 - Z3) - far, two doors
   TB = span + B + (110 / 2 - Z5 / 2) - far. The BUD 500 beside a one-door
   pocket on an 18 front is 572.5: CLAUDE.md F3's 599 assumed the door covers
   panel A as well, and the walk's 592 is the mockup's 18 + 55 + 19 pocket from
   before the owner's 22-panel rule of 13:46. F1's walk should read 572.5. My
   PREP's 594.5 (the door over A) is withdrawn: A1's three readings of 160704
   (the profile on the panel beside the cabinet, A's holes all "S + ...", TA +
   Z = 31) put panel A at the run's outer end, forward to the door's face.
2. T1 = min(KT1, 567) (D8): the 750 door on a 580 run stands M = 278 proud,
   not CLAUDE.md's 265 (T1 580 needs a 573 track HAWA does not supply).
3. `heightGroup: 'tall'` (A3 asked null): it keeps the pocket in its run. The
   tall group is what a project height change moves; with null the talls
   beside the pocket would move and the pocket would not, their top lines would
   part and `runs.js levelGroups` would cut the run there (the plinth, the top
   infill and the cornice with it). Concepta doors are 1200 to 2700 high, a
   tall run's. A3's birth matching (height, `height_custom`) still rules.
4. The door's role is `pocket_door`, never `front`: the house's lay-on trims,
   the handle and its default knob, the Blum cup ladder and the front-gap check
   that measures a front against its own carcass ends would each change or
   flag a door that by design reaches past its unit. It wears the front
   material and is finish exposed. The panels are `pocket_panel` (front
   material), the boards `pocket_board` (carcass, CLAUDE.md F6).
5. A refused door (cls null) is cut as asked but not drilled, as the LISP's
   own command drills a door only with a class; `hinges` and `setName` are null.
6. No cover, no door: a bare `computeCabinet('HAWA_POCKET')` cuts the pocket
   alone (KT = its own depth); the goldens are the LISP's two worked examples
   handed `pocket_cover`, as T80's goldens are handed `run_frame`.
7. The house's side of two-door pockets with unequal sides: each door is the
   LISP at its own span, KT1 and far; the pocket KT is the deeper door's T1 +
   RE, never past the shallower cabinet. Equal sides are the LISP's cut byte
   for byte (the test's grid).
8. `pocketCoverOf` reads `profile.doors.clearance[kind]` for `far` (the numbers
   `frontClearance.js clearanceMatrix` reads) rather than importing
   frontClearance.js, which imports types.js, which imports this module.
9. Covered units with drawer fronts are the drawer unit's family
   (`drawerStyle: 'budr'`: BUDR, its counts, the hob units, the chests): refused
   in the LISP's words (#37), the door kept.
10. Check numbers #37, #38 as CLAUDE.md; CLAUDE.md's #42 is #47 (BRIEF section 6).
11. The new goldens sit under `verify/t82/goldens/` with no script change (the
    `file: '../verify/t82/goldens/...'` road INT proved); F `F43`, gate
    `hawaPocket`, verdict "own".
