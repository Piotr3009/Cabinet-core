## The one link the fix must change

CONFIRMED as CLAUDE.md names it, and the link sits in the projector, not in the engine. `handleMarks` (src/engine/drawings/projector.js:823-826) reads only `result.drillSummary.handles`, which the engine fills only for a chosen handle (R9, src/engine/handles.js:329), so with none chosen the projector has nothing. The fix: when the project has no handle chosen, `handleMarks` asks `resolveHandle` for each front with the profile's `handles.default` (new, PROPOSED `{ type: 'knob' }`, drawn at `drawings.knobDiameter` 30), exactly as `cabinet.js` asks it (src/engine/cabinet.js:9600-9610: the same panel, unit type, hinge and frame), and draws the mark on HANDLES; the drill summary, the CNC and the BOM never see it. Row 7 proves the call gives the drilled knob's own point. Mind the shape: `resolveHandle` gives holes as `{ x, y, d, layer }` and `cabinet.js` turns them into the `[x, y]` pairs of `meta.handle` (src/engine/cabinet.js:9674-9687); the drawing's default must not write `meta.handle` (the room mounts its 3-D handle on it) nor `addDrill`. `'none'` needs a value of its own: `normaliseHandle` (src/engine/design.js:82-92) turns it into the same `null` as no choice today.
